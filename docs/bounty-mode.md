# 친구용 바운티 모드

전략 분석 버튼·패널·참고 링크·클라이언트 상태·서버 전략 필드를 제거했다. 초기 설계 문서의 분석 기능은 폐기된 계획이다.

## 규칙

1. 방에 참가하면 서버가 현재 BB × 100 칩을 지급한다. 클라이언트가 시작 스택을 지정할 수 없다.
2. 일반 핸드는 정산한 잔고로 이어간다. **정산 후 스택이 0인 플레이어가 발생할 때만** 바운티를 지급하고 전체 스택 리셋을 예약한다.
3. 탈락자 1명당 바운티 1점. 탈락자의 마지막 칩이 포함된 팟의 승자에게 지급한다. 사이드팟 승자가 메인팟 승자와 다르면 해당 승자를 따로 계산한다. 여러 명을 탈락시키면 각각 획득한다.
4. 같은 팟 공동 승자라면 바운티를 균등 분배한다. 내부적으로 1점을 60 정수 단위로 저장해 2~5인 분배를 정확히 계산한다. 표시만 소수점 셋째 자리까지 반올림한다. 칩과 바운티 점수는 별개다.
5. 폴드 승리로 칩을 얻더라도 아무도 스택 0이 되지 않으면 바운티와 전체 리셋은 없다. 퇴장/연결 종료로 떠나는 플레이어 자체에는 바운티를 지급하지 않는다.
6. 정산 화면을 7초 보여 준 뒤, 남아 있는 참가자 전원을 **다음 핸드 블라인드 기준 100BB**로 초기화한다. 패·보드·베팅은 다음 핸드에서 새로 시작한다. 버튼은 기존 순서대로 회전하며 바운티·핸드 기록은 유지한다.
7. 블라인드 예약 변경이 있으면 이를 먼저 적용한 뒤 리셋한다. 블라인드를 낸 뒤 표시되는 스택은 SB 99.5BB, BB 99BB 등이 될 수 있지만 블라인드 전 시작 스택은 모두 100BB다.
8. 준비된 사람이 2명 미만이면 시작을 기다린다. 탈락자도 리셋 대상이므로 기존 ready 상태로 다음 핸드에 자동 복귀한다. 방장이 수동 시작해도 같은 규칙을 따른다.

블라인드 최대값은 BB=10,000, SB=5,000이다. 100BB를 정수 칩으로 계산하며 기존 1,000,000 칩 최대 시작 스택 범위 안에서 유지한다.

## 서버 상태와 기록

개인 스냅샷에 `resetPending`, `resetStackBb:100`, `bountyAwards`, 플레이어별 `bountyUnits`와 표시용 `bounty`를 제공한다. 역사에는 `bounties`, `resetToBb`, 지급 후/리셋 전 `finalStacks`를 저장한다. 최근 50개 핸드 범위는 그대로다.

바운티는 팟별 칩 정산을 모두 마친 후 한 번만 계산한다. 이미 정산된 핸드를 다시 정산해도 점수/기록이 추가되지 않는다. 액션 commandId 재전송 방지도 유지한다. 칩 보존 검사는 원래 핸드 정산까지 유지하고, 리셋 경계에서만 테이블 총 칩 기준을 다시 설정한다.

현재 점수는 방 멤버십 및 JVM 메모리에 보관한다. 같은 세션의 재접속에는 유지되고 방 퇴장·재참가 또는 서버 재시작에는 초기화된다. 별도 영구 계정 점수는 없다.

## 검증

`BountyTest`: KO 점수·중복 정산·7초 후 자동 복귀·사이드팟별 KO·공동 승리 분배·KO 없는 핸드·예약 블라인드·퇴장 예외. `scripts/bounty-smoke.mjs`는 실제 두 세션의 올인/콜, KO, 명령 재전송, 7초 후 100BB 자동 재배분과 점수 유지를 확인한다.
